# Sigil

Игрушечный язык программирования, файлы `.sg`. Интерпретатор — один файл `sigil.py` на Python, без зависимостей. README — для внешних читателей, спецификация языка — `sigil.md`.

## Где что
- `sigil.py` — весь интерпретатор: `parse_lines` → `split_block` (дерево блоков по отступам) → `evaluate` (выражения) → `run` (исполнение). Цвета HUSTL — `hustl_console_color`.
- `sigil.md` — рабочая спецификация синтаксиса (источник правды для языка; при изменении синтаксиса обновлять её и таблицу в README).
- `*.sg` в корне — примеры; `main.sg` (калькулятор) и четыре простых примера прогоняются тестами. `logic_example.sg` заканчивается намеренной глубокой рекурсией (проверка `recursion too deep`), в тестах не запускается.
- `tests/test_sigil.py` — unittest.
- `editors/vscode-sigil/` — расширение VS Code (TextMate-грамматика `syntaxes/sigil.tmLanguage.json`). При изменении синтаксиса (новые сигилы/операторы) обновлять грамматику. Проверка: `vscode-textmate` + `vscode-oniguruma` (npm, во временной папке) токенизируют `.sg` и показывают скоупы.

## Команды
- Запуск: `python sigil.py file.sg`
- Тесты: `python -m unittest discover -s tests -v`

## Подвохи
- Выражения Sigil переводятся в Python-синтаксис и разбираются через `ast` по белому списку узлов (не `eval`). Перевод (`prepare_expr`/`prepare_code`) идёт только вне кавычек: строки режутся регуляркой `'[^']*'` и заменяются на `repr` содержимого. Любая новая подстановка (`%`, `#`, `$`, `!`, `&`, `|`, `true/false`) должна жить в `prepare_code`, иначе будет портить текст в строках.
- `!`, `&`, `|` превращаются в `not`, `and`, `or` — приоритет как у Python (слабее сравнений). Это сознательно: побитовые `&`/`|` связывали бы сильнее сравнения.
- Строка + число и сравнение строки с числом приводят всё к тексту (`'10' < 9` — сравнение `"10"` и `"9"`). Это задумано автором, не баг.
- `~` / `!~` переводятся в `in` / `not in`; `!~` обязан заменяться раньше общего `!` (порядок в `prepare_code` важен). Это проверка подстроки по тексту, пустая строка слева — ложь (в `evaluate`, ветка `ast.In`).
- Новый `#`-вызов: добавить имя в `SYSTEM_CALLS` и обработать в `evaluate`; неизвестные `#имя` дают ошибку с подсказкой.
- Функции получают копию окружения: присваивания внутри функции наружу не утекают, глобальные переменные читаются.
- Значения цветов в `Colors.test_known_codes` — регрессионные (текущий результат), не внешняя спецификация.
- Лимит цикла — `MAX_LOOP_ITERATIONS`; тесты подменяют его, иначе прогон занимает ~24 с.
- HUSTL — случайное имя, не аббревиатура.
